# 의미 재라벨링 모델 후보 검토

상태: **문헌 기반 후보 선정 — 다운로드·실측 전**
조사일: 2026-11-16. 기존 Qwen3-4B 제안은 검증 전 임시 선택이므로 확정하지 않는다.
목적은 현재 18,764개 학생 입력의 학습 맥락·완성 답안 요청·시도 근거를 주석하는 것이다.
프로젝트에서 최종 학습할 학생 입력 분류 모델과 라벨 생성 보조 모델은 별개다.

## 결론

우선 비교할 후보는 **Qwen3.5-9B(품질 우선)**와 **Qwen3.5-4B(자원·속도 비교)**다.
이는 공개 자료에 따른 검증 우선순위이지 우리 데이터에서 확인한 성능 순위가 아니다.
다른 계열의 비교 후보로 Gemma 4 E4B를 둔다.
4B를 무조건 선택하거나 최신 모델이라는 이유로 전체 주석에 바로 적용하지 않는다.
실제 후보 비교를 마치기 전에는 전체 의미 재라벨링 실행 모델을 확정하지 않는다.

## 후보 비교

| 후보 | 용도 제안 | 근거 | 주의점 |
|---|---|---|---|
| Qwen3.5-9B | 품질 우선 주석 후보 | 같은 계열 4B 대비 지시·문맥·다국어 공개 지표 우위 | 현 PC의 메모리 여유와 실제 속도 미측정 |
| Qwen3.5-4B | 자원·속도 비교 후보 | 같은 계열이어서 크기에 따른 품질·속도 비교 가능 | 작은 모델의 범위 판단·시도 출처 혼동을 점검해야 함 |
| Gemma 4 E4B | 다른 계열 비교 후보 | 다국어·코딩·긴 문맥 지원 | E4B는 총 파라미터 4B라는 뜻이 아님, 가중치·실행 메모리 별도 확인 |
| Qwen3-8B / 4B | 구세대 기준선, 우선 다운로드 제외 | 다국어·코드와 thinking/non-thinking 지원 | 새 계열보다 적합하다는 증거가 없어 우선순위 낮춤 |

Qwen3.5-9B 공식 카드의 동일 표에서 9B/4B 점수는 다음과 같다.

| 개발자 보고 지표 | 9B | 4B |
|---|---:|---:|
| IFEval | 91.5 | 89.8 |
| LongBench v2 | 55.2 | 50.0 |
| MMMLU | 81.2 | 76.1 |
| LiveCodeBench v6 | 65.6 | 55.8 |

출처: [Qwen3.5-9B 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B).
이 점수는 원 제작자의 평가 설정이다. 우리 한국어 혼용 대화 분류, 양자화본,
비추론 모드의 정확도 또는 Macro-F1을 의미하지 않는다.
Qwen3.5-4B/9B는 Apache 2.0 표기이며 원본의 긴 문맥 지원과 로컬에서 감당 가능한 문맥은 다르다.

## 배포 크기와 장비

Ollama 태그는 현재 같은 페이지에 복수 엔진의 아티팩트를 표시한다.

| 후보 | llama.cpp Q4_K_M 표시 | 같은 페이지의 다른 아티팩트 표시 |
|---|---:|---:|
| qwen3.5:9b | 약 6.6 GB | 약 7.6 GB |
| qwen3.5:4b | 약 3.3 GB | 약 4.0 GB |
| gemma4:e4b | 엔진별 별도 확인 필요 | 현재 첫 표시 약 9.5 GB |

출처: [9B](https://ollama.com/library/qwen3.5:9b),
[4B](https://ollama.com/library/qwen3.5:4b), [E4B](https://ollama.com/library/gemma4:e4b).
태그·해시·엔진·양자화 방식을 다운로드 시 고정해야 한다. 파일 크기는 RAM 요구량이 아니다.
문맥 KV 캐시·런타임·배치 크기 등에 추가 메모리가 필요하다.

이 세션에서 확인한 시스템 RAM은 총 약 31.6 GiB, 당시 가용 약 10.0 GiB다.
GPU/VRAM은 확인되지 않았다. nvidia-smi 미발견만으로 GPU가 없다고 단정하지 않는다.
따라서 9B를 설치하면 빠르게 처리된다고 보장할 수 없고 CPU 처리 시간도 예측하지 않는다.
현재 메모리 여유로 장문·9B 실행이 가능한지는 실제 로드·측정이 필요하다.

Gemma 4 E4B는 유효 약 4.5B지만 임베딩 포함 총 약 8B다.
작은 모델의 문맥은 128K이며 Apache 2.0 표기다.
출처: [Google 공식 카드](https://ai.google.dev/gemma/docs/core/model_card_4).
이를 기존 Gemma 3의 별도 이용조건이나 다른 계열의 메모리 특성과 혼동하지 않는다.

## 최종 분류 모델과의 관계

주석 도우미 LLM을 쓴다고 서비스에서도 같은 LLM을 매번 실행해야 하는 것은 아니다.
주석 품질이 확보되면 mBERT·XLM-R을 지도학습 기준선으로 비교할 수 있다.
이들은 사전학습 가중치만 내려받아도 우리 라벨을 바로 예측하는 모델이 아니다.

RECIPE4U 원 논문 표4는 mBERT가 XLM-R보다 좋은 결과를 보고한다.
하지만 의도 대분류 3종 micro-F1은 0.8344, 세부 13종은 0.4291이다.
흔히 인용되는 0.83을 13종 의도 분류나 우리 자기 시도 근거 과제 성능이라고 쓰면 안 된다.
또 원 논문 실험은 이후 AI 답변도 사용하므로 우리 응답 전 분류와 입력 조건이 다르다.
출처: [RECIPE4U 논문 §4.3, 표4](https://aclanthology.org/2024.lrec-main.1193.pdf).

## 다운로드 후 비교할 실험 설계

1. 다운로드 전 후보·라이선스·용량·실행 엔진·버전을 기록한다.
2. 동일한 입력·규칙·출력 스키마로 Qwen3.5-9B와 4B를 순차 비교한다.
3. 기존 AI 검토 200건은 프롬프트·출력 점검용으로만 사용한다. 사람 정답으로 간주하지 않는다.
4. 별도 학생·대화의 표본에 사람이 검토한 정답을 마련해 채택 판단에 사용한다.
5. 프로그래밍/글쓰기, 영어/한국어 혼용, 첫 턴/다중 턴, 시도/대필 경계 사례를 나눠 포함한다.
6. 항목별 Macro-F1·오탐률·미탐률과 보류율·판단 커버리지를 함께 보고한다.
7. 보류가 많은 모델이 확정한 일부에서만 높은 점수를 얻는 효과를 분리한다.
8. JSON 유효율·근거 인용의 원문 일치율·동일 입력 반복 안정성을 검사한다.
9. 실제 행 처리시간·메모리 최고치·문맥 잘림 여부를 측정한다. 전체 소요시간은 이후 추정한다.
10. 과거 AI 코드의 재붙여넣기·제공 함수 뼈대·일반 예문·문단 대필·부정 지시를 별도 점검한다.

둘 다 기준을 충족하지 못하면 작은 모델로 억지 확정하지 않고 더 큰 실행 환경이나
이용 조건을 확인한 외부 추론 경로를 별도로 검토한다.
긴 입력은 조용히 잘라 전체 이력을 읽은 것처럼 표시하지 않는다.

## 현재 수행 상태

공식 모델 카드·배포 페이지와 논문을 조사했다. 후보를 다운로드하거나 실행하지 않았다.
우리 데이터에서 어느 후보가 가장 정확한지, 처리 시간이 얼마인지는 아직 측정하지 않았다.
