## 영역별 상세

### 과목
- **초기**: 프로그래밍 과제만 다룬다. 화면·시드 데이터·시연 시나리오 모두 프로그래밍 기준이다.
- 스키마의 과목 유형(`SubjectType`)은 남겨 두어 나중에 과목을 늘릴 때 테이블을 바꾸지 않게 한다.
- **고도화**: 수학(한 단계씩 안내 + 다음 단계 예측 유도), 글쓰기, 개념 학습 정책 추가.

### 과제 파일 추출 (핵심 기능)
- **초기**
  - **md 파일부터 개발한다.** 입력은 **정해진 양식의 Markdown(.md) 파일 하나**. 다른 형식은 "정해진 양식의 md로 올려 주세요"라고 안내한다.
  - **시간이 남으면 PDF를 추가한다.** 같은 양식을 PDF로 저장한 파일을 받는다(코드 들여쓰기 · 긴 줄 줄바꿈이 깨지지 않는지 샘플로 먼저 시험).
    - 추출 코드는 "파일 → 텍스트 → 양식 파싱" 두 단계로 나눠, md와 PDF가 같은 파서를 쓰게 한다. PDF는 텍스트로 바꾸는 앞 단계만 추가한다.
  - **ThinkGuard 양식**(문항 번호·유형·선택지·정답·배점·코드 표시 규칙)을 따른 파일만 자동으로 읽는다. 양식 기준은 샘플 [c-binary-assignment.md](../spec/samples/c-binary-assignment.md)이고, 양식 문서는 따로 정리한다(확인 필요 ③).
  - **규칙(정규식)으로 나눈다. LLM은 쓰지 않는다.** 담당은 **백엔드(웹)**.
  - 추출 결과는 교수자가 과제 만들기 2단계 "문항·채점"에서 확인하고 고친다.
  - 코드 작성 문항의 **테스트 케이스가 파일에 없으면 교수자가 직접 입력**한다.
- **고도화**
  - HWP · HWPX · DOCX 지원.
  - 양식을 따르지 않은 파일은 LLM으로 문항을 나눈다.
  - 테스트 케이스 자동 생성(교수자 검토 후 적용).

### 학생 입장 · 인증
- **초기**: 회원가입 없음. **초대 코드 + 학번**으로 입장하고, 입장하면 그 클래스용 토큰을 받는다.
  - 다른 학생 학번을 입력하는 사칭은 **명단 미리 넣기 + 참여 요청 수락**으로 막는다.
  - 교수자는 이메일·비밀번호로 가입·로그인한다(JWT).
- **고도화**: 학교 계정(SSO) 연동 또는 학생 회원가입, 기기 바뀔 때 이어서 하기.

### AI 도움 설정
- **초기**: 기본은 **양식 선택**(프롬프트를 몰라도 설정 가능). 원하는 교수자만 **지시문을 직접 작성**할 수 있다.
  - 직접 쓴 지시문에도 **고정 규칙(정답·완성 코드 금지, 시도 지어내기 금지)과 누출 검사는 항상** 붙는다(불변식 I3).
  - 설정 단위는 과제마다. 클래스에는 새 과제에 채울 기본값만 둔다.
- **고도화**: 과목별 정책 템플릿 확대, 교수자끼리 설정 공유.

### 코드 실행
- **초기**: 코드 작성 문항은 서버에서 **Docker 컨테이너**로 실행한다(숨김 테스트를 학생에게 보내지 않기 위해). 구현: `backend/app/runner/`, `backend/sandbox/`.
  - 인터넷 차단, 메모리 128MB, CPU 0.5, 프로세스 64개, 파일 쓰기 차단, 5초 제한.
  - 실행마다 새 컨테이너를 띄운다. 한 번에 약 0.3–1초.
  - 시연 PC에는 Docker Desktop과 `thinkguard-runner` 이미지가 필요하다.
- **고도화**: 컨테이너를 미리 띄워 재사용(속도), 여러 언어 이미지, 백엔드와 분리된 실행 서버.

### LLM · NLP
- **초기**
  - LLM: Mock으로 개발 → 시연 때 **Ollama 로컬 모델 1개**(`qwen3:8b`).
  - 분류기: 키워드 스텁으로 개발 → NLP 팀 모델로 교체.
  - **누출 검사**(AI 답변에 정답·완성 코드가 들어갔는지): NLP 팀 담당.
  - 개념 확인 답변의 **AI 작성 점수**: 담당 확인 필요 ②.
- **고도화**: API형 LLM 선택, 쌓인 대화 데이터로 분류기 재학습.

### 외부 AI 사용 신호
- **초기**: 붙여넣기 **길이와 시점만** 기록한다. 내용은 저장하지 않는다(불변식 I5). 교수자에게 **참고 신호**로만 보여 주고 점수를 바꾸지 않는다.
- **고도화**: 학생의 이전 답안과 문체를 비교하는 모델.

### 결제
- **초기**: 요금제 선택·결제·연장은 **목업**이다. 항상 성공으로 처리하고 실제 결제 대행(PG) 코드는 넣지 않는다.
- **고도화**: 실제 PG 연동, 영수증·환불.

### 운영 환경
- **초기**: 시연 PC 한 대에서 프론트·백엔드·Ollama·Docker를 모두 실행한다. DB는 SQLite.
- **고도화**: 서버 배포, PostgreSQL(`DATABASE_URL`만 교체), 사용량이 늘면 실행 서버 분리.
